# P0070 CN105 evidence and contract

Reference: [F1p repository at7687d11](https://github.com/F1p/Home-Assistant-Mitsubishi-CN105-to-MQTT/tree/7687d11e8f4ec23de13f2c95bcdf76ebe9daebb5).

- ECODAN_Bridge.ino selects2400 baud and8E1. Original Procon main initially sets9600 (0x08009934); do not confuse startup with runtime configuration. This candidate uses independently documented2400, no automatic scan.
- Ecodan.cpp Init3: ATW connect FC5A027A02CA015D.
- Melcloud.cpp MELCloudInit3: connect ACK FC7A027A010009, **one** zero payload byte.
- EcodanDecoder.h: GET_RESPONSE0x62. EcodanDecoder.cpp Process0x04: payload[1] compressor frequency. Protocol.md confirms byte-sized whole-Hz field. Query payload is04 followed by15 zeroes; complete GET `FC 42 02 7A 10 04 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 2E`.
- Checksum is0xFC minus sum of preceding frame bytes, modulo256. Validate header, length and checksum before interpretation.
- Original binary MSP0x08009F9A–0x0800A008 configuresUSART1 base0x40013800,GPIOA pins9/10AF7. Main0x08009930–5C configures M0=0x1000,PCE=0x400,PS=0,STOP=0,AdvancedInit0x30 (no swap). Thus PA9TX/PA10RX,8 data+even parity are strong inference. Physical CN105 pin routing remains to be tested.

Implementation is newly written C, not copied reference application routines. NoSET0x41,extended-connect0x5B,serviceA3 or pump commands. Only connect and GET04 frames can be emitted. Link expiration10s triggers reconnect; sample validity separately expires10s after a valid04 reply. Never represent missing data as compressor0Hz. Parser bounds22 bytes, rejects UART errors and >100ms interbyte gaps. Polling USART1 is serviced inside RS485 transmit waits to avoid RX overrun. Test fixtures prove concurrent paths in the compiled ELF but do not validate physical pins/baud.

Modbus map: see release README. Counters are16-bit wrapping diagnostics; no persistence. Tests explicitly cover stale-value invalidation, legitimate0Hz, corrupt replies, timer wrap and simultaneous UART traffic.
