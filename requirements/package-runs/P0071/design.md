# P0071 implementation design

Keep startup/linker/platform/watchdog/RS485 and all P0070 addresses0–15. Build marker at1 advances71. CN105 framing/checksum stays in cn105.c. Add service.c state machine with two independent retained sample records and raw payloads; add transaction ownership to cn105.c (none/connect/GET04/service). One transaction owns UART from request queue until matching response or timeout. A checksum-valid unsolicited/wrong-echo frame cannot release that owner. Parser/counter behavior otherwise retained.

Connect after1s and retry3s. GET04 nominal2s cadence and priority when due. Reply deadline800ms after last byte queued to UART (includes final-byte transmission); queue timeout1s. Service retry no sooner than1000ms after prior request start, defer only for an in-flight transaction/due normal query and50ms turnaround guard. At most10 transmissions (9 retries) per service, for pending, missing or invalid replies. Other nonzero status ends that service as failure. Process27 then28; after both,20s cooldown before next cycle. Compressor polling continues between service attempts; no busy-wait/callback delay. Link lack of valid matching responses10s clears ownership, cancels operation, invalidates samples, reconnects; completed raw payloads remain available. Failed service query invalidates that channel without wiping retained data. Sample TTL60s; ages saturate65535s, compressor TTL remains10s. Timings use unsigned deltas to survive32-bit millis wrap; stale flags cannot resurrect.

New inputs16–23 service27;24–31 service28: raw completed value, experimental signed whole-degree candidate (same16bits), valid-completion flag, age seconds, latest matched status (65535 never), completion count, ever-completed flag, reserved0.32 service state (0idle,1ready,2wait-reply,3wait-retry,4cooldown,5link-down);33 active code;34 latest wire A3 status;35 current retry count;36 matched service-response count;37 service timeout/error count;38 exhaustion count;39 CN105 transaction owner(0none,1connect,2GET04,3service);40 all valid-wire A3 count;41 last service request start gap ms (saturated);42 cycle count;43 decoder evidence1=reference only, not hardware correlated.44–51 latest checksum-valid16-byte A3 payload (even wrong echo);52–59 retained completed27 payload;60–67 retained completed28 payload. Pack two bytes little-endian per register; Modbus words remain standard big-endian. Sentinels65535 require valid/ever fields because raw0xffff can also mean-1C. Max input block16 registers; no address renumbering. Full completed response reconstructable from fixed FC62027A10 header + retained payload + checksum; operator logger saves raw blocks/timestamps.

Testing: host ASan/UBSan with golden A3 packets; pending/retry cadence, statuses1/2, wrong echo, unsolicited/late frames, invalid status, corruption/truncation, queue/reply timeout, retry exhaustion, TTL/disconnect/reconnect,32-bit wrap, repeated cycles with rising normal reply count. ARM emulation injects actual concurrent serial bytes and Modbus pending/complete reads, checks whitelist and response timing. Native tests exercise longer runs efficiently; ARM time acceleration may be used only for cooldown spans, preserving byte timing in active exchanges. Build warnings/errors, deterministic forced rebuild, FF-tail and immutable original/P0070 release checks. Software release only; operator physical evidence pending, max3 attempts.

## Verification-driven refinement

The conservative ARM model uses1us per instruction (not a cycle-accurate16MHz STM32). A68-register response caused simulated RX overrun during response construction/CRC, before TX-wait servicing. Keep the proven P0070 maximum16 registers per read instead of enlarging this cooperative critical section; new addresses0–67 remain available via bounded blocks. Full16-byte completed payloads each occupy8 contiguous registers, so each is captured atomically. Modbus replies are37bytes maximum. Multi-block diagnostic snapshots are not atomic; record counts/timestamps and bracket blocks when comparing changing samples. Tests require pending/complete Modbus blocks concurrently with normal CN105, still with1us/instruction conservative model. No UART IRQ/DMA architecture change.
